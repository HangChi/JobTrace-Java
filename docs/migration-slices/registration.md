# Verified Account Registration (Feature 019)

This slice adds anonymous `POST /api/auth/register` after the registration-code issuance slice. Only this exact POST is public and exempt from the framework CSRF token. The controller preserves the existing same-origin check; absent Origin remains allowed, while explicit cross-site browser requests or a mismatched Origin are rejected. The route applies the existing `register` source limit of five attempts per minute before an optional configured human challenge and before request validation. Forwarded client addresses are not trusted by default.

Registration validates and normalizes username, recovery email, six-digit code, password and optional display name. It calls the existing PostgreSQL `verify_email_code_attempt` function with registration purpose and null owner. Wrong attempts advance the five-attempt code budget; a matching code is consumed. Verification precedes account creation, so a later uniqueness conflict still consumes the code as in the old service.

The new user uses the legacy internal authentication email and lowercased username. A Better Auth-compatible scrypt credential is inserted with the user in one transaction, with a verified recovery email and ordinary role. This transaction removes the old compensation-delete orphan risk. It creates no session and returns only the accepted sign-in prompt. Username and recovery-email conflicts remain field-specific. Responses are non-cacheable, and metrics contain only bounded outcomes and durations, never user identifiers or secrets.

The old service retains production routing, login and session issuance. Java activation requires the same registration HMAC secret as feature 018 and the existing schema/function. If human verification is enabled, configure `AUTH_CHALLENGE_VERIFY_URL` and `AUTH_CHALLENGE_SECRET`. Frontend routing, schema ownership, deployment, CI/CD and production traffic remain outside this slice. A future rollback directs only this POST path to the old service; no data migration is needed.
